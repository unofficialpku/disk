# Releasing PKUDisk

Follow [Go's publishing guidance](https://go.dev/doc/modules/publishing):
tidy dependencies, test, commit, tag, push the tag, and request the module from a
proxy. Never move or reuse a published tag; fixes get a new version.

The CLI/TUI is treated as stable within the current minor version. Compatible
fixes, diagnostics and performance tuning use patch releases (for example,
v0.3.1). Reserve a minor bump for a substantial new capability or an intentional
interface change; do not bump it for each improvement to the existing mount.

## Prepare

1. Add `docs/releases/vX.Y.Z.md` with changes, installation instructions and
   material limitations. Run `make test` and `make check` locally.
   For frontend changes, run `make ui` and `make ui-check`, and include the
   regenerated `internal/gui/web/` assets. Plain Go release builds use these
   embedded assets; Node is needed only for frontend development/validation.
2. With GoReleaser v2.18.3 installed, optionally rehearse packaging using
   `goreleaser release --snapshot --clean`. This builds all six archives locally
   without publishing. Check the native binary's `version` output.
3. Commit and push to `main`. Wait for CI to pass on that exact commit. CI uses
   three native runners; the Linux runner also cross-builds all six targets.
4. Create and push an annotated semantic version tag:

   ```sh
   git tag -a vX.Y.Z -m 'Release vX.Y.Z'
   git push origin vX.Y.Z
   ```

## Automated publication

The release workflow uses one Linux job. It checks that CI passed on `main` for
the tagged commit, rather than running the test matrix again. An untested or
failed commit cannot be released; wait for CI before pushing the tag.

GoReleaser builds Linux, macOS and Windows amd64/arm64 archives using the latest
Go 1.26 patch release, `CGO_ENABLED=0` and `-trimpath`. The job checks the native
binary's version, publishes the archives and checksums with `gh release create`,
and requests the tagged module from Go's official proxy. Rerun a failed workflow
before publication; it does not replace an existing release or its assets.

Desktop packaging sets `GOWORK=off` so the standalone root dependency graph is
also used by the release binaries. Mobile tooling remains in its own module.

## Android attachment

Update `versionName` and increment `versionCode` in `mobile/android/app/build.gradle`.
Use the shared toolchain described in `mobile/android/README.md`; run the debug
APK's full emulator E2E and build/lint the release variant with signing supplied
through the `PKUDISK_ANDROID_*` environment variables. Never commit signing keys
or passwords. Keep the signing certificate stable for in-place upgrades.

Before attaching the release APK, verify its package/version, both ABIs,
non-debuggable manifest, signature and 16 KiB zip alignment. Install the release
over the previous version on a disposable emulator and check a cold launch and
account retention. The build bundles dependency license texts generated by
`mobile/scripts/licenses.sh` under `assets/licenses/`; inspect the APK to verify
they are included. Publish exactly one `pkudisk_<version>_android.apk`.

Use one `checksums.txt` for all desktop archives and the APK. After desktop
publication, preserve every desktop digest and append the APK digest before
replacing that single checksum asset; verify the final published file against
all release binaries. Do not upload a separate Android checksum, license ZIP,
symbols or metadata asset. The desktop workflow does not require an Android
toolchain or signing secrets.

Archives include LICENSE, NOTICE, README, platform and transfer documentation,
shell completions and dependency license files. `scripts/release-files.sh`
collects licenses for all three operating systems using pinned `go-licenses`.
Generated `licenses/` and `completions/` directories are ignored by Git. Actions
use major-version tags. WinGet publication is deferred.

To verify a source installation manually, run outside the checkout:

```sh
go install github.com/unofficialpku/disk/cmd/pkudisk@vX.Y.Z
pkudisk version
```

Ensure `GOBIN`, or its default `~/go/bin`, is on `PATH`.
