# PKUDisk v0.3.0

Mounted reads now fetch small files whole and batch sequential ranges, avoiding
extra round trips when viewing a photo just larger than the old 4 MiB range.

## Read policy and tuning

- Files up to 16 MiB are fetched whole on first read when they fit the disk
  budget. A 5 MiB photo uses one authorization call and one data GET; header,
  tail, random reads and reopening reuse that data.
- Larger files start with 4 MiB ranges. Consecutive reads double the fetch size
  up to 16 MiB; a seek resets it. Contiguous demand is batched, and overlapping
  readers share the same fetch. Cached or claimed neighbours stop a batch.
- Four fetches can run concurrently per mount. Queued requests allocate no
  fetch buffer before admission and can be cancelled. Metadata and cached
  reads remain available while remote reads wait for admission or the server.
- A batch occupies one cache file and one eviction entry, with an index for
  each covered block. Complete batched files can become writable without a
  download or duplicate allocation. Pending writes remain protected.

All platforms support these flags:

| Flag | Default | Purpose |
| --- | --- | --- |
| `--read-whole-file` | `16MiB` | Whole-file threshold; `0` disables. |
| `--read-block-size` | `4MiB` | Base range for large files and seeks. |
| `--read-ahead` | `16MiB` | Maximum sequential/contiguous batch; `0` disables growth. |
| `--read-concurrency` | `4` | Simultaneous remote fetches, from 1 to 64. |

Read-size settings accept 0–512 MiB, except the base range must be positive.
Values below the base range do not shrink it. The disk budget can further
reduce ranges and read-ahead. `--cache-limit` and `--part-size` also accept
units such as `2GiB`, `64MiB` and `5MB`, as well as integer bytes.

For fewer round trips on a fast connection:

```powershell
pkudisk mount P: --read-whole-file 32MiB --read-ahead 64MiB
```

For smaller fetches and lower memory use:

```powershell
pkudisk mount P: --read-whole-file 0 --read-block-size 1MiB --read-ahead 0 --read-concurrency 2
```

On Linux/macOS replace `P:` with an existing empty directory. Larger fetches
take longer before a read returns and use more bandwidth and memory, while
reducing later round trips. `mount --help` explains these tradeoffs offline.

## Validation and upgrade

Shared tests require one fetch for a 5 MiB file, verify a sequential workload
uses 17 fetches instead of 64 with fixed blocks, and cover seeks, overlap,
concurrency limits, cancellation, cache eviction and complete-file promotion.
Linux FUSE and Windows WinFsp tests cover mounted reads and memory mapping;
Windows decodes the mounted JPEG through Go and GDI+ with one remote fetch.
The Windows Photos GUI itself is unavailable on CI; macFUSE mounting still
needs acceptance on a Mac with its extension enabled.

A live Linux mount round trip uploaded a 5 MiB JPEG, remounted, decoded it,
and verified its SHA-256 through memory mapping and repeated random reads.
The cache held one 5 MiB file. Cold decoding and mapping took 0.56 seconds;
three warm passes took 0.16 seconds total in that environment. Temporary
remote data and the clean cache were removed after verification.

Download the matching archive, verify `checksums.txt`, replace the executable
and restart existing mounts.

```sh
pkudisk version
```

Saved accounts keep their existing format. There are no command aliases.
The official Apache-2.0 license text is unchanged. WinGet remains deferred.
