# PKUDisk v0.3.2

This patch removes repeated directory-listing work identified in a real Windows
Photos freeze capture from v0.3.1.

## Cause and fix

The capture contains 6,648 directory opens but only six directory enumerations.
The adapter eagerly listed contents at every directory open and repeatedly
walked all ancestor listings to resolve known paths. Windows uses those opens
for attribute/security probes as well as enumeration, so unnecessary metadata
work delayed application operations. Some directory listings took 20–30 seconds.
The selected 5 MiB photo fetched in 0.71 seconds; a later file open waited
30.15 seconds on a metadata request that ended with HTTP 500.

- Directory opens now create a handle without loading its contents. The first
  enumeration loads one snapshot for that handle.
- Known paths resolve directly, without walking every ancestor listing.
- Fresh listing metadata satisfies file opens and attributes until the existing
  `--cache-ttl` expires; first open no longer always makes a duplicate stat call.
- Concurrent directory listings and file metadata refreshes share a fetch.
  Metadata HTTP calls run outside the file lock so cached reads stay available.
- Invalidated in-flight listings cannot repopulate the namespace cache.
  External renames/deletions invalidate obsolete paths and listings, and an old
  enumeration snapshot cannot replace newer file metadata or a pending write.

The CLI/TUI, read-policy defaults and cache TTL remain unchanged. `--verbose`
now also shows known-path reuse, lazy directory opens and shared metadata waits.

## Validation and upgrade

Windows regressions replay 6,648 directory probes with expired listings and
fresh attributes, requiring zero remote directory/attribute calls during those
probes. Native WinFsp tests exercise attribute-only `CreateFile` directory opens,
JPEG decoding through Go/GDI+, random reads and memory mapping. Tests cover
external rename/replacement and shared metadata/listing requests, invalidation,
cancellation, cached reads and concurrent writes during blocked refreshes.
The Photos GUI itself is unavailable on CI; these tests reproduce the adapter
operation pattern in the capture. Remote server latency on necessary cold
requests can still delay an operation.

Replace the executable and restart existing mounts. Capture any remaining
issue with:

```powershell
.\pkudisk.exe mount P: --verbose 2> mount.log
```

```sh
pkudisk version
```

Saved accounts and the official Apache-2.0 text retain their existing format.
WinGet publication remains deferred.
