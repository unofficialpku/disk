# PKUDisk v0.3.5

This patch fixes matched searches, mounted multi-library capacity and Windows
credential input. Existing command names and flags keep their meanings.

- Search decodes integer Unix microsecond timestamps as well as RFC3339 strings,
  handles directory size=-1, prints directory sizes as `-`, and returns an empty
  JSON array for no matches.
- Mounted total/used/free space sums every accessible library's own quota and
  usage. Writable custom/personal libraries contribute their allocation; a
  read-only library contributes used/used. A selected root counts its containing
  library, and read-only mounts report zero writable free space. Concurrent
  quota queries are shared; mutations invalidate old results.
- Windows credential prompts use the standard console input handle required by
  Bubble Tea's cancelable reader. Standard input/output remain open between
  username, password and verification prompts. One Enter submits each field.
- Text tables in `ls`, `account ls` and `util search` share the existing Lip
  Gloss table renderer. CJK/emoji/combining characters align by terminal cell
  width, numeric columns align right, and JSON output is unchanged. No dependency
  was added.
- Server-side directory copies wait for their async job even when the server
  has already returned the destination docid. Progress uses actual copied bytes,
  and same-folder copies report their generated name.

Validation now includes command-to-HTTP tests with matched file/folder results,
null/missing fields, text/JSON output, and a writable 12 TiB custom library plus
writable personal/read-only public libraries. Native kernel FUSE and WinFsp
free-space queries are checked. Windows CI drives a private real console through
username/password/verification prompts with one Enter per field.

Opt-in live acceptance exercises a saved account, matched global/scoped search,
Unicode/empty/multipart directory transfers, direct/ZIP downloads, local
extraction, file/directory/same-folder server copies, conflict handling and quota.
Transfer hashes matched; temporary remote data was removed. Search uses existing
indexed records, since new uploads can take minutes to enter the server index.
The local live mount also verified default, selected-library and read-only space
reporting. macOS kernel mounting still requires a Mac with macFUSE enabled.
