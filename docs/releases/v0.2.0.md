# PKUDisk v0.2.0

This release improves mounted-file reads for photo viewers and other applications
that make many small reads or use memory-mapped files.

## Mounted reads and unified cache

- Mount reads fetch revision-specific 4 MiB ranges and retain them in a private
  disk cache. A full read of a 5 MiB file needs two range fetches; repeated reads,
  seeks and reopening reuse the cached data.
- Concurrent requests for the same range share one fetch. Network reads release
  the file metadata lock, so metadata queries and warm reads can proceed.
- Read data and complete write files share the existing `--cache-limit` budget
  (10 GiB by default). Clean data is evicted first; pending writes and recovery
  data are protected. Whole cached files (small reads or previously flushed
  writes) can become writable without another download or double allocation.
- Reads remain available when pending writes occupy the budget. Large files
  cache only requested ranges; failed or short fetches are not retained. Clean
  cached contents are removed on unmount.
- Unix mounts now allow kernel page caching and read-only memory mapping.

Validation includes required Linux FUSE tests and Windows mounted-drive tests
for JPEG decoding (Go and Windows GDI+), small random reads and file mapping.
Shared tests cover concurrency, revision changes, cache pressure and bounded
reads of a generated 20 GiB file without creating a large local file. The
Windows Photos GUI itself is not available on the CI runner. macFUSE kernel
mounting still needs acceptance on a Mac with the extension enabled.

A live Linux mount round trip with a 5 MiB JPEG verified upload, decoding,
memory mapping and SHA-256 equality after remounting. The cold decode and full
mapping took 0.67 seconds; three warm passes took 0.19 seconds total. The disk
cache contained just two blocks (4 MiB and 1 MiB). Temporary remote data and
the clean mount cache were removed after the check. These timings describe
that test environment, not a performance guarantee.

## Command and CI cleanup

- Use `account ls` to list saved accounts. Bare `account` displays help.
- Account labels and transfer destinations use positional arguments. The old
  `account list`, `--name`, `--remote`, and `--output`/`-o` forms are removed;
  there are no compatibility aliases.
- CI uses three native runners, with all six cross-builds on Linux. A release
  uses one job and requires successful CI for its tagged commit.

## Install or upgrade

Download the matching Linux/macOS/Windows amd64 or arm64 archive and verify it
against `checksums.txt`. Replace your executable and restart existing mounts
to use the new cache. The CLI/TUI need no filesystem driver; mounting requires
FUSE on Linux, macFUSE on macOS, or architecture-matched WinFsp on Windows.

```sh
pkudisk version
pkudisk account ls
```

Saved accounts retain their existing format. The official Apache-2.0 license
text and dependency license files are included. WinGet publication is deferred.
