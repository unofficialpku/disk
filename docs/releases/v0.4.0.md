# PKUDisk v0.4.0

Commands now live at the top level, organized in the help output by purpose.
The `util` group has been removed, including its help/completion entries. This
is an intentional CLI change with no compatibility aliases:

| Before | v0.4.0 |
| --- | --- |
| `util quota` | `quota` |
| `util search KEYWORD` | `search KEYWORD` |
| `util copy SOURCE DIRECTORY` | `copy SOURCE DIRECTORY` |

`ls`, transfers, `mount`, `tui`, `account`, `recover` and CLI tools retain their
existing names. All listing subcommands use `ls`.

PKUDisk's internal sharing and external anonymous links are also available
from the CLI and TUI, using the official client's server APIs.

- `share link PATH` returns an authenticated navigation link without
  granting access. `share search NAME` finds AnyShare user/department IDs;
  `share add`, `share ls` and `share remove` manage recipient permissions.
- `link add PATH` creates an external link, with optional permissions,
  pickup code, title, validity, visit limit and phone verification. `link ls`
  shows all links for an object; `link remove ID` revokes one.
- In `tui`, select a file/folder and press `s` for sharing, recipient search,
  permission inspection and revocation, or external links. Changes have a
  review screen; link results support URL scrolling and terminal clipboard
  copying with `c` (requires OSC52 support).

Missing required input is prompted in an interactive terminal. Commands with
complete input execute directly, and omitted optional settings use the server
policy. Only `--non-interactive` controls prompting; there is no `-i` or
`--interactive`. Non-terminal scripts fail on missing input. The existing
`-a/--account`, `-t/--io-timeout`, and applicable `-j/--json` flags work here.

Internal links require login and file permissions; creating one alone grants
no access. Removal preserves unrelated and inherited rules. The official
revoke endpoint replaces an ACL snapshot without a conditional update, so avoid
concurrent permission edits. No internal-link deletion API was found.
Approval requests are reported as pending rather than active changes. These
commands send no email or recipient notifications. Server policy controls
expiry and visit limits; anonymous link metadata can briefly remain cached
after deletion. Share URLs open PKU's actual `/anyshare/zh-cn/link/` portal,
with item routing fields and without credentials or pickup codes in the URL.
No networking workaround or dependency was added.

Validation includes removed-command rejection, top-level help/completion,
populated ACLs, unrelated and inherited rule preservation,
server policy, approval responses, link pagination, recipient matching,
offline help, missing input, TUI review/cancellation and native credential
prompts. Real two-account CLI acceptance verified a recipient's download and
revocation; terminal acceptance exercised the TUI and default CLI prompts.
External pickup-code file/folder links and visit limits were tested, then
revoked. All temporary remote fixtures were removed.

```sh
pkudisk share add
pkudisk link add '/My library/report.pdf' --expires-in 168h --code Abcd1234
pkudisk tui
```
